NATIVE RUNTIME REBUILD - WINDOWS X86

This companion to rebuild-native-library.py configures/builds Aurora, the renderer/runtime. It does not link Melee, launch a game, or establish a playable port.

Prerequisites: a Windows x86 Visual Studio Developer Command Prompt, Windows SDK, Clang/Clang++, CMake 3.25+, Ninja, a real Python 3 interpreter, and Rust with the i686-pc-windows-msvc target installed. Existing dependency versions are pinned in dependencies/aurora/cmake/AuroraDependencyVersions.cmake and the renderer CMake files. Tested tools: Python3.14.7, Clang22.1.3, Rust1.99.0. The current package's runtime notices still apply.

From the desktop package folder, first configure:
  python rebuild-native-runtime.py --configure-only --build-dir "%USERPROFILE%\Documents\Codex\mrb"

Then configure/build using the same options without --configure-only:
  python rebuild-native-runtime.py --build-dir "%USERPROFILE%\Documents\Codex\mrb"

Use a short output path: the preflight's long workspace path triggered Dawn object-path warnings. A shorter output folder was subsequently built successfully; see SOURCE_REBUILD.txt. The default is build-native-runtime-release beside the script. The script does not delete existing build folders; CMake will reject incompatible existing caches.

Explicit --cmake, --ninja, --clang, --clangxx, --cargo and --rustc paths are supported when PATH discovery fails. --source can select another Aurora source tree. With no --source, the script finds dependencies/aurora in the desktop package or aurora in the development work folder. --jobs defaults to4.

The recipe selects Release, i686 Windows C/C++, shared Dawn/SDL/nod and disables the memory-card backend. It passes the actual running Python interpreter to CMake, avoiding Windows Store launcher stubs. Keep execute-target-for-cmake.py beside the driver: it lets CMake run Windows x86 generated-code tools on this Windows host. It does not emulate gameplay or implement a console emulator.

Without a source map, upstream dependency downloads are required. Optional --dependency-source-map FILE takes a JSON object such as {"DAWN":"C:/cache/dawn-source"}. Keys are FetchContent names; values must be existing dependency source folders. In this explicit cached-source mode the script disables both FetchContent downloads and Dawn's separate dependency fetcher. A complete, consistent cache is required; missing sources are errors. Never describe this mode as a clean download or a fully self-contained source bundle.
